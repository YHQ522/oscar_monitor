多数据库架构

本系统通过 SSH 远程连接 + CLI 命令行 方式采集数据，支持四种数据库类型：

数据库标识CLI 工具默认端口监控视图
Oscar oscar isql 2003 V$ 系统视图
MySQL mysql mysql 3306 information_schema / performance_schema
PostgreSQL postgresql psql 5432 pg_stat_* / information_schema
Oracle oracle sqlplus 1521 V$ / DBA_ 视图
系统根据数据库类型自动选择对应的 CLI 命令和监控 SQL，无需手动切换。

6 步向导添加服务

添加和编辑均使用统一的 6 步向导流程：

#步骤说明
1 环境 选择操作系统（Linux/Windows）、填写显示名称、设置自动刷新间隔（秒，0=关闭）
2 SSH 连接 远程主机 IP、SSH 端口（默认 22）、登录用户名和密码。Windows 需安装 OpenSSH Server
3 采集项 勾选需要采集的数据库类别（5 类）和 OS 检查项（内存/磁盘/CPU/日志）。提供快速配置下拉：全部 / 仅DB / 仅OS / 最小
4 数据库 选择数据库类型（Oscar/MySQL/PostgreSQL/Oracle）、是否持久化日志、是否加入启停管控、数据库连接信息（主机/端口/用户/密码/库名/isql路径）。
若步骤③未勾选任何 DB 采集项，此步骤自动跳过。
5 应用 配置关联应用（可选）：应用名称、启停脚本模板（systemctl/service/init.d/自定义脚本/sc）或自定义命令
6 完成 测试 SSH 和数据库连接，确认无误后保存

常见问题
Q: 支持哪些数据库？

Oscar（神通）、MySQL、PostgreSQL、Oracle。添加服务时选择对应类型，系统自动适配 CLI 命令和监控 SQL。

Q: 数据采集返回空或报错

① 检查采集项是否勾选 ② SSH 连接是否正常 ③ isql/mysql/psql/sqlplus 路径是否正确 ④ 数据库用户是否有查询权限。

Q: 测试连接失败

SSH：检查端口 22 是否开放、用户名密码是否正确。Windows 需安装 OpenSSH Server。
数据库：检查 CLI 工具路径，如 isql -h 主机 -p 端口 -d 库名 -U 用户/密码。

Q: 健康评分不显示

需先执行采集获取数据，评分在采集完成后自动计算。采集失败则评分不更新。

Q: 趋势图没有数据

至少需要 2 次采集才有折线。趋势数据在内存中，重启服务后清空。建议开启定时采集。

Q: 登录被限制

连续 5 次密码错误后同 IP 封禁 15 分钟。等待倒计时结束或联系管理员。

Q: 我能看到哪些页面？

取决于管理员分配的权限：仪表板 / 服务管理(查看/编辑) / 启停管控(查看/执行)。admin 拥有全部权限。

Q: 巡检报告能导出什么？

Excel 格式，包含所有选中服务器的 DB 采集数据和 OS 检查数据。支持按服务器分 Sheet 或按类别分 Sheet。
